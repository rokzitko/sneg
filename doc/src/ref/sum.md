# sum

## Usage
- `sum[expr, {i, j, ...}]` represents the symbolic sum $\sum_{i, j, \ldots} \mathrm{expr}$ over the dummy indexes *i*, *j*, ....
- `sum[expr, {}]` is *expr*.

## Details
- `sum` is a formal sum: the range of the indexes is not specified and the sum is never evaluated term by term. Typical uses are band Hamiltonians $H = \sum_{k\sigma} \epsilon_k c^\dagger_{k\sigma} c_{k\sigma}$, lattice Hamiltonians $\sum_R (\ldots)$, and operators such as the density $\rho_q = \sum_k c^\dagger_{k+q} c_k$.
- The indexes should be declared, so that SNEG treats them as scalars and not as unknown operators. The declaration determines the index type and the value of `sum[1, {i}]`, the number of values of the index:

| `snegfreeindexes[i]` | generic index; `sum[1, {i}]` stays unevaluated |
| `sneglatticeindexes[{R}, Ns]` | unit cells of a periodic lattice; `sum[1, {R}]` is $N_s$ |
| `snegmomentumindexes[{k}, Ns]` | crystal momenta; `sum[1, {k}]` is $N_s$ |
| `snegspincomponentindexes[a]` | Cartesian spin components; `sum[1, {a}]` is 3 |

- Kronecker deltas of linear combinations such as $\delta_{p,k+q}$ are solved, and lattice sums of Bloch phases are performed, only for lattice and momentum indexes, see `sumSimplifyKD` and `fourier`.
- The index list is sorted, so `sum[a, {k, i}]` is `sum[a, {i, k}]`.
- Factors that do not depend on the summation indexes are moved in front of the sum; a summand *z* free of all indexes gives `z sum[1, {...}]`.
- Nested sums are merged, `sum[sum[a, {i}], {j}]` is `sum[a, {i, j}]`.
- In `nc`, a sum is moved to the front when the other factors do not contain its indexes: $c^\dagger_1 \sum_k c_k = \sum_k c^\dagger_1 c_k$.
- A product of sums in `nc` is combined into a single sum. Dummy indexes that occur in both factors are renamed: the second `k` becomes `k1`, `k2`, ... (the first name that is not among the indexes of the two sums and does not occur in the expression). The new index is declared with `snegfreeindexes` and inherits the properties of the original: realness, lattice or momentum type and size, spin-component type.
- `komutator[sum[a, ...], sum[b, ...]]` renames the indexes of the second argument in both terms of $ab - ba$.
- `conj[sum[a, {...}]]` is `sum[conj[a], {...}]`.
- `sum` does not distribute over `Plus` automatically: `sum[a + b, {k}]` and `sum[a, {k}] + sum[b, {k}]` are different expressions. Use `sumExpand` to distribute and expand the summand, `sumCollect` to combine sums, `sumSimplifyKD` to perform sums over Kronecker deltas, and `sumFullSimplify` for a heuristic combination of these steps. `sumThread` threads a sum over a list.
- `sum[expr, {}]` is *expr*; a sum without indexes is the summand.
- Sums that contain only scalars are scalars (`isnumericQ` gives `True`), so they can be moved out of `nc` products.
- The automatic renaming is controlled by the global variable `sumAutoRename` (default `True`). With `sumAutoRename = False`, colliding indexes are not renamed and the message `snegsumJoin::overlap` is issued.

## Developer Notes
- `sum` has no attributes. The simplification functions are rule lists applied with `ReplaceRepeated`; some of them are available as `rulesumDistribute`, `ruleExpandUnderSum`, `ruleFullSimplifyUnderSum`, and `rulesumFactor`.
- The renaming is done by the internal `snegsumJoinWithRenaming`; new names are generated by `ssJWRnewname`, which also declares the new index and copies the index properties.
- The definitions of `sum` evaluate patterns: the left-hand side `sum[a_, {k}]` itself evaluates to `a_ sum[1, {k}]`, because `a_` does not contain `k`. Patterns for sums in rules and in `Cases` must be wrapped in `HoldPattern`, or use a pattern for the index list, `sum[a_, it_List]`.
- The internal marker `scalar[x]` declares *x* as a scalar and is used inside sums for speed; `rulestripscalar` removes it.

## Examples
### Basic Examples
Kinetic energy of a band of electrons, $H = \sum_{k\sigma} \epsilon_k c^\dagger_{k\sigma} c_{k\sigma}$:
```wl
snegfermionoperators[c];
snegfreeindexes[k, sigma];
snegrealfunctions[eps];
H = sum[eps[k] number[c[k], sigma], {k, sigma}]
```
The product of two sums is a double sum; the second dummy index `k` is renamed:
```wl
nc[sum[c[CR, k, UP], {k}], sum[c[AN, k, UP], {k}]]
```

### Scope
Factors that do not depend on the summation indexes are moved in front of the sum:
```wl
snegfermionoperators[c];
snegfreeindexes[k, sigma];
snegrealconstants[x];
snegrealfunctions[eps];
{sum[2 x eps[k] c[CR, k, UP], {k}], sum[x, {k, sigma}]}
```
The order of the indexes does not matter, and a sum without indexes is the summand:
```wl
{sum[eps[k], {sigma, k}] === sum[eps[k], {k, sigma}], sum[eps[k], {}]}
```
---
Nested sums are merged:
```wl
snegfreeindexes[i, j];
snegrealfunctions[g];
sum[sum[g[i, j], {i}], {j}]
```
---
Hermitian conjugation:
```wl
snegfermionoperators[c];
snegfreeindexes[k, sigma];
snegrealfunctions[eps];
conj[sum[eps[k] c[CR, k, sigma], {k, sigma}]]
```
---
Operators that do not depend on the summation index are moved into the sum:
```wl
snegfermionoperators[c];
snegfreeindexes[k];
nc[c[CR, 1, UP], sum[c[AN, k, UP], {k}]]
```
---
Commutators of sums, $[\sum_k n_{k\uparrow}, \sum_k c^\dagger_{k\uparrow}]$, with the renamed index `k1`:
```wl
snegfermionoperators[c];
snegfreeindexes[k];
r = komutator[sum[number[c[k], UP], {k}], sum[c[CR, k, UP], {k}]]
```
The Kronecker delta is eliminated with `sumSimplifyKD` after expanding the sums, $[N_\uparrow, \sum_k c^\dagger_{k\uparrow}] = \sum_k c^\dagger_{k\uparrow}$:
```wl
sumSimplifyKD[sumExpand[r]]
```
---
Vacuum expectation value of a product of sums, $\langle 0 | (\sum_k c_{k\uparrow}) (\sum_k c^\dagger_{k\uparrow}) | 0 \rangle = \sum_k 1$:
```wl
snegfermionoperators[c];
snegfreeindexes[k];
vev[nc[sum[c[AN, k, UP], {k}], sum[c[CR, k, UP], {k}]]]
```
```wl
sumSimplifyKD[%]
```
---
Lattice and momentum indexes have $N_s$ values, so sums over indexes that do not appear in the summand are evaluated:
```wl
sneglatticeindexes[{R}, Ns];
snegmomentumindexes[{q}, Ns];
snegrealfunctions[eps];
{sum[1, {R}], sum[eps[q], {q, R}]}
```
Indexes generated by renaming inherit the declaration:
```wl
snegfermionoperators[ck];
nc[sum[ck[CR, q, UP], {q}], sum[ck[AN, q, UP], {q}]]
```
```wl
{momentumindexQ[q1], latticesize[q1]}
```

### Applications
Equation of motion of a band electron. For $H = \sum_{k\sigma} \epsilon_k n_{k\sigma}$, $[c_{p\uparrow}, H] = \epsilon_p c_{p\uparrow}$ and $[H, c^\dagger_{p\uparrow}] = \epsilon_p c^\dagger_{p\uparrow}$:
```wl
snegfermionoperators[c];
snegfreeindexes[k, p, sigma];
snegrealfunctions[eps];
H = sum[eps[k] number[c[k], sigma], {k, sigma}];
{sumSimplifyKD[sumExpand[komutator[c[AN, p, UP], H]]], sumSimplifyKD[sumExpand[komutator[H, c[CR, p, UP]]]]}
```
The total number of electrons is conserved:
```wl
sumFullSimplify[komutator[sum[number[c[k]], {k}], H]]
```
---
Fermi sea. With `SEA` ordering, the vacuum expectation value is the ground-state average in the Fermi sea (states with $k < 0$ occupied), and the kinetic energy is $\sum_{k\sigma} \epsilon_k \theta(-k)$; the remaining sum over $\sigma$ gives the spin degeneracy 2:
```wl
snegfermionoperators[cs];
ordering[cs] = SEA;
snegfreeindexes[k, sigma];
snegrealfunctions[eps];
vev[sum[eps[k] number[cs[k], sigma], {k, sigma}]]
```

### Properties & Relations
`sum` does not distribute over sums automatically; `sumExpand` and `sumCollect` convert between the two forms:
```wl
snegfreeindexes[k];
snegrealfunctions[f, g];
s = sum[f[k] + g[k], {k}];
{s == sum[f[k], {k}] + sum[g[k], {k}], sumExpand[s], sumCollect[sumExpand[s]]}
```
---
Kronecker deltas are summed by `sumSimplifyKD`:
```wl
snegfreeindexes[i, j];
snegrealfunctions[f];
sumSimplifyKD[sum[KroneckerDelta[i, j] f[i], {i}]]
```
---
`sum` does not thread over lists; use `sumThread`:
```wl
snegfreeindexes[k];
snegrealfunctions[f, g];
{sum[{f[k], g[k]}, {k}], sumThread[sum[{f[k], g[k]}, {k}]]}
```
---
Sums of scalars are scalars:
```wl
snegfreeindexes[k];
snegrealfunctions[f];
isnumericQ[sum[f[k], {k}]]
```

### Possible Issues
A pattern `sum[a_, {k}]` is evaluated before it is used, because `a_` does not depend on `k`; the rule does not match:
```wl
snegfermionoperators[c];
snegfreeindexes[k];
snegrealfunctions[eps];
H = sum[eps[k] number[c[k], UP], {k}];
sum[a_, {k}]
```
```wl
H /. sum[a_, {k}] :> a
```
Use `HoldPattern`:
```wl
H /. HoldPattern[sum[a_, {k}]] :> a
```
---
An operator that contains the dummy index as a free index is not moved into the sum, because that would capture the index. The product stays unevaluated:
```wl
snegfermionoperators[c];
snegfreeindexes[k, p];
nc[c[CR, k, UP], sum[c[AN, k, UP], {k}]]
```
Use different names for free and dummy indexes:
```wl
nc[c[CR, p, UP], sum[c[AN, k, UP], {k}]]
```
---
A nested sum over the same index is merged without renaming, and the index then appears twice:
```wl
snegfreeindexes[k];
snegrealfunctions[f];
sum[sum[f[k], {k}], {k}]
```
---
With `sumAutoRename = False`, dummy indexes in products of sums are not renamed, and the result is wrong:
```wl
snegfermionoperators[c];
snegfreeindexes[k];
Block[{sumAutoRename = False}, nc[sum[c[CR, k, UP], {k}], sum[c[AN, k, UP], {k}]]]
```
---
Sums over spin indexes are not expanded into the terms $\sigma = {\uparrow}, {\downarrow}$, and the number of values of a generic index is unknown:
```wl
snegfermionoperators[c];
snegfreeindexes[k, sigma];
{sum[number[c[k], sigma], {sigma}] == number[c[k]], sum[1, {sigma}]}
```
Write spin sums with `number`, `hop`, ... (which include the spin sum) or with `Sum` over `{UP, DO}`:
```wl
Sum[number[c[k], s], {s, {UP, DO}}] == number[c[k]]
```
